# Этапы реализации

Каждый этап — отдельная проверяемая порция работы и отдельный Git checkpoint.
Ни один этап здесь не помечен как уже выполненный.

## M1. Запускаемая основа

Workspace `apps/web`, `apps/api`, `packages/contracts`; TypeScript strict;
выбранные совместимые версии, один lockfile, formatter/linter/typecheck/test/build.
Next.js с базовой responsive-страницей; NestJS с конфигурацией и health endpoint;
PostgreSQL в Docker Compose и TypeORM с миграциями.

Реализовать только Crew как первую бизнес-сущность: id, stable code, name, active,
workEnvironment INDOOR/OUTDOOR, serviceArea text, timestamps.
Seed из 10 команд запускается отдельно и повторно не создаёт дубликаты/не перезаписывает изменения.
Публичного CRUD команд пока нет. Персональных данных в M1 нет.

Готово, когда: реальная health-проверка делает SELECT 1; при недоступной БД возвращает 503,
UI показывает недоступность, а не fake success; миграция создаёт таблицу и FK/unique, где применимо;
двойной seed оставляет 10 команд; данные сохраняются после рестарта сервисов;
lint/typecheck/unit tests/build проходят; integration test прогнан на выделенной тестовой БД.

## M2. Вход, роли и команды

User, CrewMember, ADMIN/DISPATCHER/CREW_MEMBER, безопасная аутентификация и logout,
backend authorization, login-страница, защищённые `/backoffice` и `/crew`.
Выбрать и документировать cookie/token-механику и защиту mutation-запросов;
не хранить долгоживущий токен в localStorage. При cookie-auth учитывать CSRF и Origin.

Seed: 1 admin, 1 dispatcher, 40 сотрудников; по 4 в каждой из 10 команд.
Секрет для seed передаётся локально, не коммитится и не сбрасывается при повторном seed.
Управление командой, участниками, активностью, специализацией и областью работ;
контакты внешних специалистов без аккаунта. Disabled user не имеет доступа.

Готово, когда: нет входа с неверным паролем, logout инвалидирует авторизацию,
dispatcher видит все команды, crew не может выполнять административные запросы напрямую,
в ответах нет password hash и других секретов; seed повторяемый и недеструктивный.

## M3. Заказы, товары и ручные платежи

Order/OrderItem/Payment/ActivityLog. Обычные формы заказа и данных доступа/контактов.
Dashboard, поиск, фильтры, пагинация. Только реальные persisted данные.
Журнал платежей, вычисленные сумма/оплачено/остаток, void с причиной.
Защитить от двойного платежа и конкурентной переплаты.

Готово, когда: заказ создаётся и остаётся после reload; формы валидируются на backend;
запрещённые поля не принимаются; дробные/отрицательные/слишком большие денежные значения
отклоняются; 2 одинаковых запроса платежа создают 1 запись; financial данные недоступны crew.

## M4. Визиты, назначения и календарь

Appointment/CrewAssignment, подтверждение клиента, длительность, одно или несколько назначений.
Рабочие окна и недоступность команд; TaskTemplate и копирование обязательных задач в назначения.
Общий календарь day/week с часами, список и multi-select фильтр команд.
Параллельные визиты разных команд видны одновременно.
Редактирование времени формой; перенос не создаёт новый Order.

Готово, когда: пересечение одной команды запрещено, разных команд разрешено;
недоступная/disabled команда не назначается; все команды многокомандного визита проверяются;
два конкурентных запроса в одно окно не проходят одновременно; устаревшая версия даёт 409;
проверены буфер, дневные границы и DST; перенос сохраняет историю.

## M5. Работа команды и доказательства

Today/upcoming/open/completed, детали, разрешённые переходы статусов,
товары и накопленные количества, задачи/чек-листы, заметки, фотографии и документы.
Issues с типом и товарами, partial outcome, return visit reason и оставшаяся работа.

Готово, когда: сотрудник не видит чужой заказ даже по прямому URL/API;
команда закрывает только своё назначение; неправильный переход отклоняется;
повтор запроса не удваивает прогресс; доставленная мебель со сборкой не закрывает заказ;
файл недоступен постороннему; ограничения размера и типа проверяются;
пустая ошибка/повторный визит без причины не принимаются.

## M6. Задержки и предложения перепланирования

Отдельные actual times/estimatedFinishAt; панель рисков; поиск свободных окон на сегодня/следующие дни,
возможность другой команды; предложение без автоматического каскадного переноса.
Подтверждение диспетчера, проверка актуальности слота, отметка согласования клиента.
Повторный приезд после частичной работы создаёт новый Appointment того же Order.

Готово, когда: следующий визит не переносится сам; слот после задержки учитывает буфер;
новый слот повторно проверяется при сохранении; исходный заказ и история не теряются;
ранее завершённые работы не появляются снова в чек-листе нового приезда.

## M7. Подписи и закрытие

Подписи клиента и сотрудника, результат визита, отказ/отсутствие с причиной и проверкой диспетчера.
Финальное завершение с проверкой обязательных работ, issues и повторных визитов.

Готово, когда: незакрытый issue блокирует финальное COMPLETED, но не запись фактически сделанного;
одна завершённая команда не закрывает остальных; неоплата не стирает выполненную работу;
подпись связана с неизменяемым снимком; повторный submit не дублирует результат.

## M8. Realtime, проверка и демонстрация

Socket.IO или иной согласованный транспорт без отдельного микросервиса;
авторизованные каналы, событие после commit, refetch на reconnect и fallback.
Итоговый seed из 30–50 вымышленных заказов разных стадий.
Responsive polish, loading/empty/error states, README, env guide и Docker demo runbook.
E2E сценарий: заказ → назначение → доставка/сборка → задержка → перенос → issue →
повторный визит → подписи → закрытие.

Готово, когда: событие не раскрывает чужие данные, reconnect восстанавливает актуальность;
два браузера отражают изменение; воспроизводится свежая установка и демо по README;
сформирован список известных ограничений. Deploy выполняется только с разрешения пользователя.

## Правило перехода

Если проверка BLOCKED из-за окружения, этап не объявляется полностью принятым.
Можно описать что реализовано, но локальная проверка остаётся обязательной.
Следующий этап запускается отдельным запросом пользователя.
