# Furniture Delivery — старт разработки в Codex

Это пакет контекста и заданий, а не реализованное приложение. Исходный код, зависимости,
миграции и запускаемые сервисы появятся после выполнения первого задания Codex.

## Начало

1. Распакуйте архив и откройте папку `furniture-delivery-codex-start` как проект в Codex.
   Папку можно переименовать в `furniture-delivery`.
2. Для нового проекта создайте Git-репозиторий. Не заменяйте существующий код этим архивом.
3. Передайте Codex содержимое `prompts/01-foundation.md`.
4. Проверьте изменения и фактически выполненные проверки. Не переходите к M2,
   пока M1 не запускается на вашем компьютере.
5. После проверки сохраните отдельный Git-коммит. Следующее задание находится в
   `prompts/02-identity-and-crews.md`.

Для уже установленного Codex CLI, из распакованной папки:

```bash
git init
codex
```

Можно использовать локальный интерфейс Codex вместо CLI. Не требуются OpenAI API-ключи
в создаваемом бизнес-приложении: Codex здесь инструмент разработки, а не функция продукта.

## Первая цель

Не красивый календарь на фиктивных данных, а проверяемая цепочка:

`Next.js → NestJS → PostgreSQL`

В M1 веб-страница показывает настоящий результат проверки API и БД.
В БД существует таблица команд, миграция и идемпотентный seed из десяти команд.
Данные команд пока не публикуются через открытый бизнес-API: доступ появляется в M2.

## Предлагаемые настройки, которые можно изменить

Рабочая зона — `Europe/Rome`, валюта — `EUR`, язык интерфейса — английский.
Это допущения для старта, а не подтверждённые компанией требования.
Имена сотрудников не должны быть зашиты в бизнес-логику.
Рабочие часы и буфер переезда — настройки, а не константы внутри календаря.

## Безопасность тестового

Используйте только вымышленные клиенты, адреса и контакты.
Не публикуйте приложение с открытыми бизнес-эндпоинтами или общедоступными паролями.
Не загружайте реальные платёжные реквизиты, документы и подписи.
Не включайте платные сервисы и production-интеграции без отдельного решения.

## Как принимать работу Codex

Просите список изменённых файлов, выполненных команд, результатов тестов и известных ограничений.
«Команда добавлена» не означает «команда выполнена».
«Код написан» не означает «сценарий проверен».
Если Docker или браузер недоступны агенту, он должен явно отметить непроверенные пункты;
их необходимо выполнить локально, прежде чем считать этап принятым.
